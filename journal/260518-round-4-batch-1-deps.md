# 2026-05-18 — Round 4, batch 1 (dependabot security upgrades)

Round 4's security batch. GitHub Dependabot flagged six advisories
on `main` after round 3 shipped (1 high, 4 moderate, 1 low). All
six landed under patch-version bumps of three packages — `svelte`
direct, `devalue` and `cookie` transitive through `@sveltejs/kit`.

Round-4 plan: `.engineering-team/improvement-plan.md` (W1).

## What shipped

`svelte` direct bump in `package.json` lifted `devalue` along with
it (Svelte 5.55.7 pulled `devalue@5.8.1` as a deduped install).
`cookie` was stuck — the latest `@sveltejs/kit` (2.60.1) still
constrains `cookie@^0.6.0`. Adding an `overrides` block to
`package.json` forced the lockfile to resolve `cookie@0.7.2`
everywhere. `npm audit` went 4 lows → 0.

| Advisory | Severity | Package | Before → After | Vector |
|----------|----------|---------|----------------|--------|
| GHSA #8 | High | devalue | 5.6.4 → 5.8.1 | DoS via sparse-array deserialization |
| GHSA #12 | Med | svelte | 5.55.0 → 5.55.7 | XSS via DOM clobbering of internal framework state |
| GHSA #11 | Med | svelte | 5.55.0 → 5.55.7 | SSR XSS via spread attributes |
| GHSA #10 | Med | svelte | 5.55.0 → 5.55.7 | SSR XSS via insecure Promise serialization |
| GHSA #9  | Med | svelte | 5.55.0 → 5.55.7 | ReDoS in `<svelte:element>` tag validation |
| GHSA #1  | Low | cookie | 0.6.0 → 0.7.2 (via override) | Out-of-bounds chars in name/path/domain |

## Files touched

- `package.json` — `svelte: ^5.51.0` → `^5.55.7`; new `overrides: { cookie: ^0.7.0 }`.
- `package-lock.json` — regenerated by `npm install`.

That's it. No source changes — none of the four Svelte CVEs touched
APIs we use (we don't spread untrusted props, don't `hydratable()`
untrusted Promise inputs, don't take `<svelte:element this={…}>`
from user input, and don't have user-controlled DOM `id` attrs that
would shadow framework state). The runtime patch is sufficient.

## Why `overrides` on cookie, not a kit bump

`@sveltejs/kit@2.60.1` (latest at time of write) still has
`"cookie": "^0.6.0"` in its dependencies. There is no kit release
with the bumped range yet. `npm audit fix --force` would downgrade
`@sveltejs/kit` to `0.0.30` to satisfy the constraint — meaningless.

The `cookie@0.6 → 0.7` change is purely validation that rejects
out-of-bounds characters in cookie names/paths/domains. SvelteKit's
cookie usage runs through its own `Cookies` API which produces
ASCII-only names and paths, so the new validation never trips. The
override is safe.
